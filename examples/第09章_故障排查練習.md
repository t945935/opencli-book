# 第 9 章實作｜用症狀、證據與下一步排錯

## 練習
將每個情境寫成「症狀 → 可觀察證據 → 安全下一步」，不猜測隱藏原因。

| 症狀 | 證據／命令 | 下一步 |
|---|---|---|
| CLI 找不到 | `opencli --version` 與 shell 錯誤 | 檢查安裝和 PATH；不要重複安裝多份 |
| 瀏覽器橋接不通 | `opencli doctor` | 依診斷檢查擴充功能與 daemon，再重試 |
| 多個 profile | `opencli profile list` | 請使用者指定；不可自行挑選 |
| 頁面元素消失 | `opencli browser <session> state` | 重新檢查新頁面狀態，重新尋找元素 |
| adapter 無資料 | 該 adapter 的 `--help`、錯誤輸出、官方文件 | 確認參數、登入狀態、地區限制；遮蔽敏感資料後回報 |

## 命令練習

```bash
opencli doctor
opencli profile list
opencli browser --help
```

## 規則
先收集最小必要診斷；不要把完整日誌、私密網址或瀏覽器 Cookie 貼到公開 issue。不要用 `--trace` 或 verbose 收集資料前忽略其可能包含的頁面上下文；先讀目前版本說明並檢查輸出。

## 驗收
每個情境都有實際證據來源、可逆的下一步和停止條件。工具仍無法連線時，正確結果是「未完成」，不是捏造成功輸出。
