# 第 12 章實作｜從查詢到可交接的唯讀流程

## 目標
完成一個低風險、可重跑、可人工抽查的公開資料工作流程。

## 步驟

1. **定義任務**：複製 `../templates/網站任務規格.md`，限定查詢 Hacker News 公開熱門文章前三筆；禁止留言、投票、收藏及發文。
2. **記錄環境**：執行 `opencli --version`，保存工具版本；不用瀏覽器的 adapter 任務不需要為此啟動 Chrome。
3. **核對指令**：執行 `opencli hackernews top --help`，確認 `--limit` 和 JSON 格式。
4. **執行唯讀查詢**：

   ```bash
   opencli hackernews top --limit 3 -f json > /tmp/opencli-top.json
   ```

5. **檢查結構**：解析 JSON，確認最多 3 筆且每筆有標題、URL；空回應或格式錯誤就停。
6. **核對來源**：人工打開一筆公開 URL，確認頁面內容和擷取標題相符。
7. **交接**：用 `../templates/結果驗收紀錄.md` 記下版本、命令摘要、驗收結果與任何限制。

## 失敗分支
- 命令不存在：重新檢查 `opencli list` 和本機版本；不要猜 adapter 名稱。
- 服務無回應：記錄時間與錯誤，稍後重試前先確認不會重複執行寫入（本例唯讀）。
- URL 或標題不一致：標示未驗證，不轉述為事實。
- 需要登入或出現非預期操作：停止並回報。

## 完成定義
只有在 JSON 結構檢查和來源抽查都完成時，才標記通過；否則分別記錄「部分通過」或「未驗證」。本流程不會保存私人資料，也不對網站寫入。

## 驗證狀態
查詢命令已在 OpenCLI 1.8.8 實際執行。JSON 解析示例可由讀者對自己的輸出執行；瀏覽器抽查步驟未在本教材發布環境自動化測試。
